# 0006 Measuring text-to-SQL accuracy

`evals/run_eval.py` asks Claude each question twice, connected to the MCP server: with `describe_tables` and `run_sql` only (plain text-to-SQL), and with `list_metrics` and `query_metrics` added and preferred.

Expected answers come from reference SQL run at eval time, so they follow the data. A question can list other defensible answers (`accepted_sql`).

A right number isn't enough if the answer leaves out what makes it misleading. Hard questions name the point a good answer must make (`must_mention`), and Claude Opus 5.5 grades it. The first question set used keyword matching instead, which missed a correct answer worded differently.

The eval goes through the MCP server over HTTP, so it measures what a real client gets. Results and what they showed: `evals/RESULTS.md`.
